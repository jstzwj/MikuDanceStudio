# 内部接口兼容性核查与回归

## 范围与结论

本轮整理 D3DX、COM 和模型接口的类型、参数名称及注释，检查字段宽度、缓冲布局、资源所有权和失败分支。2026-11-03 完成数组构造顺序、PMD 分配、模型析构、附件父模型检查、效果初始化及 HRESULT 判定的兼容性修正。

验证覆盖下文列出的接口和生成场景，不代表全程序等价，也不代替真实模型、MME 效果和 AVI 导出的完整验证。

## 实现约定

| 项目 | 当前行为 |
|---|---|
| 数组构造回调 | 计数器递减，元素指针递增，从首元素到末元素调用构造回调；计数为零时不调用。十个生产调用点使用无副作用的 `IdentityCtor`。 |
| PMD 骨骼数组 | 按实际骨骼数分配骨骼表、四字节游标及单字节状态数组。 |
| 模型析构 | 保持描边 VB、主 VB、IB 的释放和清空顺序；不修改姿势追踪存储及其计数、录制状态。 |
| 附件父模型 | `parentModel == -1` 表示未附着。 |
| 效果初始化 | 资源效果创建传入空错误输出；按 HRESULT 决定清理，依次释放阴影表面、HDR 纹理、阴影深度并清除后处理标志。SM2 的格式查询和 `SetInt` 位于返回值检查前。 |
| HRESULT 判定 | VB／IB 创建、索引锁定、截图创建和 blit 使用精确零值判断；顶点锁定、多重采样探测和设备创建保留符号判断；设备能力查询忽略返回值。 |
| PMX 资源输出 | 创建 VB／IB 时直接写入模型字段，非零返回值下也能通过生产析构访问已输出的资源。 |

部分异常输入路径缺少边界保护；上述约定不表示为畸形模型或无效父模型索引提供完整保护。

## 类型与数据布局

- PMD 主顶点和描边顶点分别为 32、16 字节，描边颜色为 `0xFF000000`。磁盘顶点读入 38 字节，CPU 顶点记录步长为 40 字节。
- PMD GPU 索引使用 16 位，CPU 展开索引使用 32 位，两者按各自类型访问。
- PMX 附加 UV 数为 0..4 时，主顶点步长分别为 32、48、64、80、96 字节；描边顶点保持 16 字节。
- 骨骼／表情关键帧游标每项四字节，活动／选择／物理状态每项单字节。
- `englishUI` 表示界面语言标志；附件材质使用 68 字节的 `D3DMATERIAL9`，保留有符号索引比较。
- 截图格式使用固定 `int` 底层类型的 `D3DXIMAGE_FILEFORMAT`，未知扩展名分支显式保留现有 32 位原始格式值。
- 网格加载输出使用具体网格和缓冲类型；材质缩放使用单精度。NVAPI 设备参数使用 `IDirect3DDevice9*`，外部句柄保持不透明类型。

## 回归覆盖

`model_ui_edit` 使用可观察顺序的构造回调，覆盖零次、三次及有符号计数退出条件。x64 `native_host_query_test` 的四组构造顺序对照通过，计数分别为 `0`、`1`、`3`、`0xFFFFFFFF`；宿主查询接口 **7536 次比较通过**。

`model_lifetime_test` 和 `kinect_tracking` 检查析构保留姿势追踪指针和状态，由测试夹具自行释放保留的分配。`pmx_buffer_failure` 使用 CPU 缓冲设备覆盖创建／锁定负值失败、加载失败后的槽位清理，以及五个 `S_FALSE` 案例：主 VB、描边 VB、IB、16／32 位索引锁定。正值案例同时检查 API 输出指针归属和生产析构清理。

两架构完整 Release 构建通过。最终选定 CPU 回归为 **x64 80/80（87.59 秒）、x86 76/76（62.06 秒）**，无失败或跳过；每架构另有 23 个依赖 GPU 的用例明确排除，不能将这些结果称为全量 CTest 通过。补充 API 输出指针归属断言后，两架构 `pmx_buffer_failure` 单独构建并复跑通过。修改的 C++ 文件通过格式检查，`git diff --check` 通过。

生成 PMD 和 PMX 各覆盖两个视角、三种描边强度；主／描边缓冲均逐字节一致。两组场景各只有三个顶点，属于有明确覆盖目标的夹具，不代表真实复杂模型的完整覆盖。

本轮原生 D3D9 设备报告 `HAL=0x8876086A`、`NULLREF=0x8876086C`，场景数值验证使用 CPU 缓冲。尚未执行截图文件输出、效果初始化编译、最终像素或 AVI 输出复验。

JUnit 结果位于各构建目录的 `alignment-cpu-final-{x64,x86}.xml`。
