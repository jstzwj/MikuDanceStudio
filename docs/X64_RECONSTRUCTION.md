# x64 重建基准和证据规则

本项目的行为基准是 **MikuMikuDanceE v9.32 x64**，效果语义基准是 **MMEffect v0.37 x64 English**。x86 反编译和旧移植代码可帮助恢复算法与含义，但不是 x64 字段、指针宽度、浮点求值或容量的替代证据。目标是可维护的行为重建，不是声称取得原作者源码。

| `MMEffect_v037x64_English/MMEffect_v037x64_English/MMEffect.dll` | `74b3f5882a3bad28131cbc57994e2f960938e6ca850fc7139018ce4822bd87dc` |

IDA 导出的 MMD 地址以 `0x7FF7CB420000` 为 image base。重开数据库或受到 ASLR 影响时应记录 image base/RVA，不把一次会话的 VA 当作永久运行时地址。session ID 是工具运行状态，不是长期证据标识。

当前实现与验证结果见 [移植状态](PORTING_STATUS.md)，历史修复依据通过 Git 历史查阅。旧 `reports/` 目录不在工作树中，不能把其链接当作当前证据。

## 如何判定一致

1. 每项行为明确输入、前置状态、参考版本和可观察输出：文件消费、窗口状态、骨骼姿态、顶点/材质、物理轨迹、效果脚本执行顺序等。
2. 反编译用于导航。涉及有符号比较、浮点中间值、分支合并、对象大小和调用约定时，再看反汇编和调用者/消费者。Hex-Rays变量名不视为原作者命名。
3. 静态对应、编译通过、布局断言、独立测试、原版A/B回归分别记录；不能相互替代。“扫描过文件”也不等于逐函数对照。
4. 差异需说明适用范围：普通有效文件、边界有效文件、损坏文件、硬件/插件缺失、释放失败等。不为追求字面一致复制C++未定义行为。
5. 严格数值比较须记录编译选项、D3DX运行库、Bullet版本和时序输入。x64基准的D3DX为`d3dx9_43`；x86材料里出现的`d3dx9_32`和x87算序不能直接外推。实时物理比较需控制步长与初始状态。

## 数值兼容

x64 的单精度运算和 x86 的 x87/双精度表达式分别维护。即使数学公式相同，也不能合并浮点写回阶段或重新结合求值顺序；直接定位与播放推进的四元数插值同样需要保留各自的除法、倒数乘法和舍入阶段。

`LinearMath/btMmdMath.cpp` 隔离了 VC9 x86 求值方式，其 `/arch:IA32 /fp:precise /O2 /Oi /GL- /RTC-` 选项只作用于该编译单元。修改时保留 x87 扩展精度中间值、`volatile float` 写回点、有序求和的 `noinline` 边界，以及调用方的精度控制和舍入模式。MSVC 的 `long double` 为 8 字节，不能仅靠替换类型恢复 x87 求值。

[数学回归](../tests/mmd_math_test.cpp) 的 [golden 数据](../tests/mmd_math_golden.hpp) 来自旧实现，不能用替换后的实现重新生成。x87 三角函数近似可能随 CPU 变化；相关用例使用[冻结的旧实现](../tests/mmd_math_x87_reference.cpp)在当前 CPU、相同精度及舍入模式下生成对照值，历史汇编仅编译进 x86 测试程序。

## 运行时类型和兼容边界

- 新业务代码使用具名对象、成员和明确的拥有关系。不要以 `At<T>(bytes, offset)`、旧虚表槽或地址表作为运行时模型。
- 原版布局断言是校验证据工具，不是要求独立可执行程序永远保留原版对象布局。现有平面布局仍用于迁移期间的对应检查；应逐子系统迁移生产者与消费者，避免只有外观类型化而底层仍取旧偏移。
- 磁盘格式、运行时内存和外部COM/插件ABI分开维护。例：模型运行时名称容量50字节，PMD名称磁盘字段仍20字节；不能将运行时`sizeof`直接套用到格式读取。
- `RawPad` 只表示未恢复区域。恢复具名成员必须核对所有读写者、大小、对齐、所属对象和释放方式。不能随意将padding命名为未经证明的功能。
- 非拥有的Win32/COM/Bullet指针可以是显式借用；拥有的数组/对象要有配对分配释放与清晰生命周期。不要把裸指针数量当作错误数量。
- MME 的渲染语义、效果参数、pass/script时序纳入宿主。宿主已经能主动提供上下文，无需代理d3d9.dll、IAT patch或虚表注入。历史 `mmhack` 目录名不构成重新实现注入的需求。

## 布局头的真实维护方式

`model_layout.hpp`、`bone_layout.hpp` 是**人工维护**的运行时结构及断言。历史注释提到的 `scripts/gen_model_layout.py`、`scripts/gen_bone_layout.py` 不在本仓库，不能宣称可运行它们重建。

`scripts/regen_layout_pins.py` 是旧pin表整理脚本，读取已存在的输入并带特定历史字段映射；它不是二进制布局发现器，也不是上述两个头文件的生成器。不要因文件名带regen就把当前结构交给它盲目重写。

修改布局时应：记录参考锚点 → 恢复语义成员 → 同步全部消费者 → 更新准确断言 → 运行相关独立测试和完整构建 → 用真实输入补足A/B行为测试。不要先改断言去迁就一个没有证据的结构。

布局修复必须依据原版初始化及全部读写者恢复连续成员，并分别验证 x64/x86。仅移动一个 padding 来通过局部测试不足以证明布局正确。

## 2026-10-25：四处架构相关访问复核

通过 IDA MCP 核对上述 x64 原版，并以 x86 v9.32 的对应函数交叉检查。下列 x64 地址使用 RVA，image base 为 `0x7FF7CB420000`。

| 访问 | 原版依据 | 实现约束 |
|---|---|---|
| 骨骼注册下拉框 | x64 RVA `0x59B00`；x86 VA `0x410040` | `boneCount` 在 x64 为 `+12560`、x86 为 `+11652`；使用 `ModelRecord::boneCount/boneTable` 和骨骼名称成员。类型筛选的 `<7` 为有符号字节比较，保留 `==8` 分支及 JP/EN 顺序。 |
| 附件目标前后切换、滚动 | x64 RVA `0x719D0/0x71BF0/0x71E40`；x86 VA `0x4391D0/0x439520/0x41A460` | 使用 `AccessoryRecord::order/rowSelected`，分别对应 x64 `+1197/+1212`、x86 `+1181/+1196`。扫描全部 255 个附件槽，保持全局轨道顺序、相邻顺序缺失时的不同回退、滚动及刷新顺序；加一按 `int` 比较，255 不回绕到 0。x64 `+1196` 是阴影开关，不得写入。 |
| 物理地板开关 | x64 RVA `0x500BC/0x500FB`；x86 VA `0x48B779/0x48B7A9` | 原版替换 `btCollisionObject::m_collisionFlags`，启用为 `1`、禁用为 `-1`。本地 Bullet 2.75 的 `setCollisionFlags` 仅赋值，自动匹配 x64 `+0xE0` / x86 `+0xD4`；不改激活状态和其他物理字段。 |
| 显示剪贴板诊断转储 | 本项目的 `frame_clipboard.cpp` 生产者与 `DisplayClipboardRecord` | 按具名记录访问，步长由类型确定为 x64 40 / x86 24 字节，指针以原生宽度输出，保留 JSON 字段名和数量保护。这是本项目诊断功能，无对应的原版窗口行为。 |

附件顺序、剪贴板嵌套指针及数量字段增加布局断言；回归见 `edit_target_layout`、`physics_floor`、`frame_state_dump`。三项覆盖具名字段和上述边界分支，刷新函数使用计数替身，控件及地板碰撞体使用真实 Win32/Bullet 对象。它们不替代原版完整 GUI 的端到端 A/B 或长期物理轨迹对照。

## 2026-10-25：关键帧、顶点及 COM 访问整理

VMD 加载、关键帧粘贴和范围缩放共用 `BoneClipboardRecord`、`MorphClipboardRecord`、`IkClipboardState` 与 `SelectorClipboardState`。注册接口显式表达记录类型；骨骼输入保留可变引用，因为固定轴修正会修改输入四元数。输入布局由 `offsetof` 断言约束，VMD/PMM 磁盘读写仍使用各自的字段长度，不能用运行时记录的 `sizeof` 替代。

轨道分配使用原有标量 `operator new`，字节数由运行时类型和容量计算；初始化改用成员。模型表情／显示容量、全局轨道容量及撤销深度集中引用常量。操作枚举贯穿命中测试、拖动和光标恢复；Kinect 导出使用有名称的槽位。对话框 ID、滚动消息、顶点 FVF 与部分 PNG 资源 ID 使用已有或新增的名称。时间轴列宽 13 与轨道行高 14 保持区分。

整理时核实并修正了以下行为差异：

| 位置 | 原版依据 | 修正 |
|---|---|---|
| 表情名称查找 | EXE x64 VA `0x7FF7CB4EACF0` 按 `192 * index` 查找，逐条递增下标；x86 记录为 136 字节 | 原代码在已类型化的指针上执行 `+= 136`，实际跨过 136 条记录。改为 `++mrec`。 |
| VMD 单字节标志 | EXE x64 VA `0x7FF7CB48D7C2`、`0x7FF7CB48E67E`、`0x7FF7CB48E714` 只比较 `LOBYTE` | 透视、显示和 IK 标志按字节读取并归一化，防止骨骼物理标记 3939 的高字节影响后续零值。 |
| 背景四边形 | EXE x86 VA `0x417078`、x64 VA `0x7FF7CB488887` 均将首顶点 RHW 写为 `1.0f` | 补齐原先遗漏的首顶点写入，六个顶点使用同一个经过布局断言的类型；保留三角形顺序及坐标计算精度。 |
| MMDxShow 配置指针 | 原版 x64 DLL VA `0x180001913` 构造、`0x180001695` 设置、`0x180001070` 释放均访问 pin `+0x638`；`0x180005396` 清理 `0x464` 字节显示区 | 原布局及断言误写为 `+0x630`，并把显示区描述为发生越界。恢复 `0x464` 字节显示区及自然对齐后的 `+0x638` 指针，删除错误说明；x86 保持 `+0x5A0`。 |

MMDxShow 的已知字段以成员表达，跨 COM 基类转换由 C++ `static_cast` 完成；受保护字段通过集中访问器读取。媒体类型、分段缓存、锁和线程字段补有两架构断言，原有 GUID、虚表顺序、对象大小和未知填充保留。

新增 `key_registrars`、`vmd_record_decode`、`background_quad`、`mmdxshow_protocol` 四项回归。前两项在隔离副本恢复旧的表情步进及 VMD 整字比较后，x64/x86 均能检出错误。VMD 用例逐字段生成 v1/v2 文件，覆盖插值转置、相机／灯光／阴影及模型标志；注册用例检查名称匹配、链表、反转、撤销调用以及乱序 IK／外部父骨骼字段。背景用例检查全部 168 字节。COM 探针无需注册 DLL，同样可对原版 x64/x86 DLL 运行，覆盖接口查询、引脚枚举、配置指针、状态及结束锁存后的返回值。

这些验证覆盖本轮修改；未据此宣称完整 GUI、Kinect 实机或 AVI 编码管线已全面等价。
