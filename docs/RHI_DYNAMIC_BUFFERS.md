# 动态 GPU 缓冲复用与 Vulkan 资源回收

本批将逐帧变化的逻辑资源版本与物理 GPU 分配分开。编辑器和离屏调用继续通过
`SceneRenderer` 执行同一流程；CPU `id/version` 的不可变内容契约、旧版本拒绝和
PreparedFrame 的失效规则保留。

## 共享缓冲池

首次发布的几何保持原有静态分配；同一场景、同一逻辑 ID 出现新版本后，提升为动态缓冲。
顶点与索引均可复用，不要求上层生产者标记动画资源。纹理不进入该池。

- 单版本流每个逻辑 ID 最多四个存储槽，包含当前分配。初始静态分配完成后释放，
  因而创建计数的生命周期上限是一次静态创建加四次动态创建。
- 复用必须匹配场景、资源 ID、用途、字节数及索引格式，且该槽的最后提交已经完成。
  仍属于当前场景版本的存储不会被覆写，即使 GPU 已完成。
- 空闲槽可立即完整上传；达到上限时只等待该资源最早的退休提交。没有完成则准备失败，
  原 PreparedFrame 仍可提交。尺寸变化可以淘汰已完成的旧尺寸槽。
- 显式同时发布同一 ID 多个版本的回放仍合法；为保留全部当前版本，上限提高到
  当前与待准备分配数加一和四之间的较大者。普通逐帧生产者只发布一个当前版本。
- 准备失败后，已借出的槽进入受管退休列表，不进入当前版本，也不会丢失所有权。
  卸载清空该场景的池；设备替换先等待旧设备相关提交，再释放全部槽并保留 CPU 快照。

DX11 使用完整 `WRITE_DISCARD` 上传，驱动可能自行重命名底层存储。这里的创建计数
表示 RHI 物理缓冲对象创建，不等同于驱动内部的显存分配次数。DX9 的动态资源会在 reset
失效，因此该共享池不提升采用此生命周期的后端。

## DX12 staging 复用

每个动态 DEFAULT 缓冲保留一个匹配的 UPLOAD 分配，记录其复制提交 fence。
完整替换仅在 staging 未排队、复制已完成时复用它。尚未完成的复制、同一提交前的多个更新
或局部写入使用独立的 staging 任务，保持排队数据不可变；这些资源继续由帧 fence 保护。
销毁时 DEFAULT 与保留的 UPLOAD 分配各自按安全完成边界回收。

## Vulkan 按最后使用回收

顶点、索引、材质／阴影采样以及 Pass 附件和图像复制记录资源最后使用的 timeline 值。
`Destroy` 立即使句柄失效、推进 generation；原生 buffer/image/view/memory 保留到该资源
自己的 timeline 完成。`BeginFrame`、`Destroy` 与完成等待会轮询回收，不调用全队列等待。

可映射缓冲的 `Upload` 遇到该缓冲尚未完成的 GPU 使用时返回 false，且不改动字节；直接
Device 调用者必须在完成后重试。共享渲染器已经只提供完成的槽，正常路径不会遇到此拒绝。
完成了的资源不会因队列还有无关工作而等待。

帧命令／descriptor 池仍等待自己的帧完成。transfer 命令池只等待自己的上次 transfer，
纹理上传和验收回读仍同步等待本次 transfer，未引入异步纹理流或专用传输队列。
缩放、reset 和设备销毁仍保留其必要的整体完成边界。未跟踪提交失败和真实设备丢失
沿用现有阻止继续提交／设备替换路径。

## 回归与观测

`rhi_scene_renderer` 的延迟设备覆盖连续千帧、池上限、等待具体旧 token、尺寸变化、
同时发布多版本、过期版本、上传／目标准备失败回滚、卸载及设备重新绑定。

`rhi_dynamic_buffer_{dx11,dx11-warp,dx12,dx12-warp,dx12-debug,dx12-warp-debug,vulkan,vulkan-debug}`
完全使用离屏设备。240 帧同时更新顶点和索引，混合 indexed／nonindexed 绘制，检查
创建数、复用数、退休积压、原生分配和等待；输出与同姿态的新建缓冲严格逐字节比较。
另覆盖重复提交、缩放、设备替换、卸载，以及一个提交前的多次完整／局部更新。
DX11 局部动态上传仍按其已有契约拒绝，随后以完整上传验证相同结果。

`rhi_vulkan_resources` 和 `rhi_vulkan_validation` 使用仅限离屏测试的主机 timeline
阻塞队列。队列确定阻塞时，无关缓冲仍可上传和销毁；忙碌的 indexed／nonindexed 缓冲
拒绝写入；六个使用中的缓冲／纹理／附件立即失效，但原生分配保留。主机解除阻塞并等待
对应提交后，退休列表清空，验证层错误为零。测试设备析构也会解除阻塞，避免失败时挂起。

`SceneRendererStats` 区分逻辑上传、物理缓冲创建／复用／槽等待和 resident／pooled／retiring
字节；Vulkan 另区分 timeline、idle、frame、transfer 等待及忙碌上传拒绝。原生分配统计
包括帧常量和回读／纹理 staging，必须比较合适区间的差值。
`EditorViewport::Statistics()` 提供只读快照；实际 `FrameDriver` 基准在计时外取样。

最终验证：x64 的 93 项离屏／隐藏窗口用例中，69 项通过，24 项因未配置外部素材路径
明确跳过；另 11 项资源契约／CPU 运行时用例全部通过。本地 Sour Miku 的三后端导入、
两种自阴影、严格重复输出和跨 API 重建另行验证通过。x86 的 21 项用例中 19 项通过，
两项因缺少 32 位 Vulkan 验证层跳过。x64／x86 主应用、关闭诊断的三后端版本、关闭诊断
且关闭新后端的版本均构建成功。全部图形测试使用离屏设备或从不显示的父窗口。

## Sour Miku 完整驱动记录

2026-10-29，TITAN Xp、Release x64，139,692 顶点／25 材质，1280×720、无自阴影。
每档预热三帧，记录 60 帧；与[帧所有者基准](RHI_FRAME_OWNERSHIP.md)采用同一驱动和

输入在计时外生成，计时覆盖实际主驱动、CPU 蒙皮、覆盖层、RHI 及仿真尾部，不含回读。
