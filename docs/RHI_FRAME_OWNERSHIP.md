# 编辑器帧渲染选择

`RenderFrameScene` 先准备一次当前帧，再选择实际执行的渲染器。
支持的 DX11／DX12／Vulkan 帧不再执行 DX9 的 Clear、BeginScene、阴影、场景、
覆盖层绘制或屏幕纹理捕获。主驱动使用 RHI 的呈现结果，不再呈现 DX9 后缓冲。

## 更新时序

`PrepareFrameSceneInputs` 保留相机／灯光、立体状态、精灵、消息门禁和模型更新的原有顺序。
原版在绘制后执行的 `PlaybackCatchup`、Kinect 和 `PhysicsFrame` 仍由 `FrameDriver`
执行一次；该驱动随后生成的文字与选择框仍供下一帧使用。这批不提前推进仿真或重排原版输入。

播放主驱动回归发现原有附件状态只有 55 槽，但播放会遍历 255 槽。活动标记与游标现均使用
完整的独立运行时存储，不再访问恢复布局中的局部数组；保留 ABI 布局并验证末尾槽、应用间
隔离及视口状态不被覆盖。

选用 RHI 时，`PrepareEditorModelGeometry` 使用现有 morph／蒙皮工作函数生成当前 CPU
版本，正常帧不锁定或写入 DX9 模型顶点缓冲。兼容模式也复用这份准备结果，避免重复蒙皮。
仍选用 DX9 的帧和显式原生诊断保留原有更新／对照路径。

## 同帧回退

1. 功能检查不通过时，隐藏 RHI 子窗口并选择 DX9。
2. 资源准备、提交或呈现失败时，隐藏 RHI 子窗口，用本帧相机、材质和 CPU 几何执行 DX9。
3. `UploadPreparedEditorGeometry` 复制已准备顶点，不再次执行 morph、不发布第二个 CPU 版本，
   也不推进动画或物理。CPU 布局／发布失败时，原生工作函数直接使用已完成 morph 的输入。
4. 如果原生缓冲上传也失败，不提交含旧几何的帧；主驱动停止旧后缓冲的 Present，并继续轮询
   DX9 恢复。设备进入可重置状态后仍可请求原有重建。

已选择的后端不会因临时回退而改变。功能限制解除后可恢复 RHI；设备失败仍通过菜单
`Recreate device` 或重新选择后端重试。共享控制器重建暂停设备前先完成有效的 reset 协议，
再等待并释放旧资源；不把 ResetPending 当成已确认设备移除，不绕过完成令牌。

DX9 与 RHI 的 `screen.bmp` 历史随渲染所有者交接失效：成功进入 RHI 后释放未再更新的
原生捕获，离开 RHI 时重置共享捕获游标。恢复首帧按无历史状态绘制，并在该帧末重新捕获，
避免显示交接前的旧图像；未建立跨 API 的历史图像复制。同一后端连续帧的前一帧采样与
操作轴／HUD 之前的捕获时点保持不变。

诊断构建中的显式原生证据目录、场景历史、完整场景和输入审计请求使用 DX9 作为原生对照。
普通诊断构建仍执行所选 RHI。比较阈值不变。

## 可观察计数

`MMDApp::FrameRenderingStats()` 提供每个应用实例的累计计数：

| 字段 | 含义 |
| --- | --- |
| `preparations` | 通过消息门禁的帧准备次数 |
| `geometryUpdates` | 已加载且有顶点的模型更新次数 |
| `rhiFrames` | 成功呈现的 RHI 帧 |
| `rhiFallbacks` | 选择了 RHI、最终转入原生路径的普通帧 |
| `legacyScenes` / `legacyPasses` | DX9 BeginScene 成功次数／场景 Pass 执行次数 |
| `fallbackGeometryUploads` | 从本帧准备结果完成的原生模型上传次数 |
| `lastBackend` / `rendered` | 本次实际使用的后端／是否完成了可呈现帧 |

测试比较计数差值；正常 RHI 帧要求 DX9 场景与 Pass 均不增加。诊断构建同时比较
原生 indexed／triangle／line 绘制桥计数，避免仅依据分支标记判断。

## 隐藏窗口门禁

`editor_frame_dx11/dx12/vulkan` 使用实际 DX9 设备和从不显示的父窗口，生成 PMD／PMX
并调用生产代码的 `RenderFrameScene` 与 `FrameDriver`。覆盖：

- 严格重复输出、合成右键拖动、当前帧身份及主驱动的播放 catch-up。
- 每帧只准备一次、每模型只发布一次；正常 RHI 帧不改动原生模型缓冲中的哨兵数据。
- CPU 场景准备拒绝、线框兼容回退、暂停设备后的提交失败与重建。
- 回退后的原生缓冲逐字节等于本帧 CPU 结果；失败回退画面与相同状态的直接 DX9 帧严格相等。
- 原生上传失败时不呈现旧画面；生成 `screen.bmp` 附件验证回退前后历史失效与重新捕获。
- 三后端与 DX9 切换、缩放、卸载／重新接入模型及真实主驱动的更新边界。

上述帧计数覆盖不等于所有编辑辅助图形已建立跨 API 像素门禁，也不模拟驱动重启或物理 GPU
移除。既有后处理、自阴影、屏幕捕获和生命周期测试继续作为各自行为的门禁。

本批最终验证：x64 的 66 项离屏／隐藏窗口回归、x86 的 10 项编辑器与运行时状态回归，
以及本地 Sour Miku 的三后端真实 PMX 导入用例全部通过。Release 主应用在 x64、x86、
关闭诊断但启用三后端、关闭诊断及新后端的四种配置下均构建成功。测试未显示顶层窗口。

```powershell
ctest --test-dir build-x64/build -C Release --output-on-failure -R '^editor_frame_(dx11|dx12|vulkan)$'
build-x64/build/Release/editor_frame_test.exe vulkan 'C:\assets\model.pmx' --benchmark 30
```

基准在 1280×720、无自阴影下执行实际 `FrameDriver`，预热三帧后记录平均值、p50 和 p95。
静态档使用零 delta；动画档逐帧生成骨骼矩阵变化，PMX 还改变一个 morph，并以 1/60 秒运行
驱动尾部的正常仿真。它测量 CPU 端墙钟时间，包括帧准备、蒙皮、覆盖层、RHI、主驱动及其
仿真尾部；计时内没有图像回读。骨骼变化的测试输入在计时外生成，未加载真实 VMD。
隐藏窗口不包含桌面合成或交互延迟，不能直接换算用户日常编辑器帧率。

本机 TITAN Xp、Release x64、Sour Miku PMX（139,692 顶点／25 材质）的 30 帧记录：

| 后端 | 静态平均 / p50 / p95（ms） | 生成动画平均 / p50 / p95（ms） |
| --- | --- | --- |
| DX11 | 9.602 / 9.556 / 10.200 | 12.670 / 12.448 / 13.242 |
| DX12 | 10.060 / 10.010 / 12.748 | 18.984 / 16.852 / 40.694 |
| Vulkan | 11.272 / 10.892 / 14.300 | 15.061 / 14.813 / 17.885 |

各档 DX9 场景 Pass 计数均为零。此记录用于下一批动态缓冲／回收优化的基线，
未测量本次改动之前的同条件整帧开销，因此不声明加速比例。素材仅从本地只读加载。

## 仍存在的边界

编辑器启动、相机／覆盖层准备、字体及兼容回退仍依赖 DX9 设备。CPU 覆盖层目前仍通过原有
顶点生产过程取得，尚未全部改为独立 CPU 存储。这批消除了正常 RHI 帧的 DX9 场景绘制，
没有移除整个编辑器的 DX9 依赖。接续批次已落实[动态缓冲复用与 Vulkan 回收](RHI_DYNAMIC_BUFFERS.md)，
并补充新的完整驱动测量；通用 MME 着色器绑定继续按[审查计划](RHI_REVIEW_2026-10-29.md)推进。
