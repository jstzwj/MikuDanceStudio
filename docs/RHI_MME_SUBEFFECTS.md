# DefaultEffect turns, scene nesting and render-target mips

Supported legacy scene effects can now schedule offscreen child effects and
nested scene carriers through DX11, DX12 and Vulkan. The editor builds one CPU
frame from the existing MME/SAS assignments before choosing its backend. No
native DX9 scene draw is needed to prepare a supported RHI frame. An unsupported
descendant or illegal dependency rejects the entire shared frame and retains
the same-state DX9 fallback.

## Native scheduling remains authoritative

The native and portable paths share offscreen assignment discovery. They use
the existing ordered `DefaultEffect` matcher, subset/whole-object overrides,
visibility rules, relative child paths and `main_default` resolver. The exporter
does not parse a second assignment language. Turn IDs scope child bindings and
successful script-parameter writeback; bindings whose owners disappear are
retired during discovery.

Offscreen targets execute in reverse discovery order, so a discovered child's
product is completed before its parent's consumer. Each turn lowers the same
prepared geometry, current draw parameters and selected child technique. It
clears its color/depth attachments, renders its objects and nested scene effects,
then generates its requested mip chain. The assembled frame validates physical
aliases, initialization and feedback after every scope has been expanded.
Queued host background/grid draws remain in the base scene, matching the native
background replay gate; they do not become geometry in every child target.

Scene carriers follow the native host's unique display-order map, including
accessory precedence for duplicate positions. Enter walks backwards and resume
walks forwards around `ScriptExternal`. Wrapping an existing frame in ascending
carrier order preserves that nesting. Buffer geometry retains the original
quad inputs, with a separate CPU identity for each target extent.

## Explicit mip contract

`FramePass::generateMips` is a standalone operation without draws or attachments.
The target must have an initialized, stored base level and a complete RGBA8 mip
chain. Sampling a multi-level render target before generation is rejected.
Any subsequent base-level write/discard or frame invalidation makes the chain
unavailable until it is generated again. Stale handles and generation inside an
active pass are rejected by Null and the native backends.
Readback still returns level-zero rows; it does not concatenate the mip chain.

- DX11 uses an autogen-capable target and `GenerateMips`.
- DX12 downsamples each level with linear-clamp sampling, separate per-level
  SRVs/RTVs and explicit subresource transitions. Descriptor storage belongs to
  the completion-protected frame; mip draws count against the preparation budget.
- Vulkan separates the base-level attachment view from the full sampling view,
  blits levels with linear filtering and transitions each subresource before
  returning the entire image to sampled use. Existing per-resource completion
  tracking also covers these commands.

Format capability queries expose `renderMips`. Preparation checks capabilities
and work budgets before submitting a frame. Mips are generated after the whole
offscreen turn, including its resumed postprocessing, matching native MME
bookkeeping. They are not generated implicitly on every target switch.

## Current bounds

The portable walk is bounded to 32 discovered offscreen turns and eight scene
wrappers per scope. Each imported scene still has one supported technique, one
`ScriptExternal` and represented `Draw=Buffer` passes. Scene nesting follows
the native base frame's carrier inventory; assigning a scene-class child
to an ordinary model selects fallback instead of inventing an extra scene walk.
Offscreen targets require explicit `ClearColor` and `ClearDepth`; viewport extents and paired fixed
`Width`/`Height` are represented. Capture attachments must match their scope's
extent. Shared identities retain the preceding batch's rebuild and lifetime rules.

Autogenerated offscreen mips accept RGBA8 and native `Miplevels=0`/automatic full
chains. Partial chains, HDR mips, depth sampling and
multi-level targets with `MipFilter=NONE` remain unsupported. A native offscreen
lookup miss/hide skips its draw. Explicit host-material forwarding (`none`, or
an unresolved ordinary main pipeline) remains same-frame DX9 fallback; built-in
self-shadow sampling within child turns is also outside this batch. Generic
child shaders replace inherited built-in shadow state rather than accidentally
requesting the host's shadow pipeline.

The following batch adds ordinary FX9 MRT/HDR captures and positive viewport
ratios; see [relative target rules](RHI_MME_LEGACY_MRT.md). Smaller scene captures
and wrapping an existing MRT capture in another MRT scene still use DX9 fallback.

The public examples establish unlit material, child and nested Buffer execution.
They do not establish arbitrary material/depth behavior or full Ray support.
Unmodified Ray continues to use DX9 until its remaining shader/state/resource
requirements are represented.

## Regression scope

`rhi_render_mips_contract` checks initialization, explicit generation order,
invalid commands, rewriting and expired handles. Native variants sample an
explicit lower mip, check all RGBA channels, rewrite/repeat, resize and replace
the device; DX12 debug and Vulkan validation variants require zero errors.

`mme_legacy_source` imports the four new original CC0 fixtures unchanged.
`mme_scene_plan` permits an external shared product while retaining private
read-before-write rejection; final frame validation checks its actual producer.
`mme_portable_shader_*` checks removal of inherited built-in shadow bindings.

`editor_frame_*` uses generated PMD/PMX files and never-shown windows. It compares
the two-level child/mip chain and nested carriers against the real DX9 MME walk,
including RGBA, `hide`, `main_default`, unmatched rows and reversed carrier order.
This scene oracle uses equal 160x120 offscreen targets with host HUD disabled;
the host has no HUD atlas. Existing overlay regressions remain separate.
It also checks unsupported-child/partial-mip fallback before RHI uploads,
restoration, repeat, resize, device recreation and switching among all backends.
Existing frame-owner assertions require one update and zero DX9 scene draws on
successful RHI frames. Existing copy, MRT/HDR, sharing and native Ray fallback
gates retain their comparison standards.

successfully.

x64 DX11 editor rerun passed. The x64 18-gate log contains 108 scene-oracle
comparisons, all with maximum RGBA delta zero; the final x86 log contains
