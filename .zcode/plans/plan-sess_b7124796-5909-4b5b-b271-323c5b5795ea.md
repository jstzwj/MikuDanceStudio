# MME 场景重绘机制根本性实现（对齐原版 MMEffect v0.37 x64 二进制）

## 目标

让 Ray-MMD 这类 scene/postprocess 效果真正出画面：把移植版缺失的"ScriptExternal 单步挂起/恢复 + 每轮 pass 记录"原版机制完整实现。全部机制已用 IDA + 配套反编译库（`OpenMMD\decompiled\MMEffect`，1544 函数）逐函数核实，以下每条都有原版 VA 证据。

## 逆向结论（实现的基准事实）

1. **数据模型**：每个 ModelData 携带 SAS 绑定字段：+0x358=持久化运行上下文指针、+0x360=scriptClass、+0x364=scriptOrder（即移植版的 renderClass：1=preprocess→passPlanA，2=postprocess→passPlanB）、+0x368=标志。赋值路径 `fcn_18002ca80` 在整对象赋值 scene/sceneorobject 效果时写入（ray.x 同名规则自动挂 ray.fx 的写入点）。移植版字段已在 model_data.h 但从未被写入（"Phase 3 未释放"）。
2. **帧机制**：规划器 `fcn_18005b9e0` 设 `ExpSetRenderRepeatCount(|orderedPlan|+1)`；宿主 while 循环多跑的轮里，轮首绘制触发 `fcn_18005d130`（PassBookkeeping）：RunPostEffect → 编排 `fcn_18005da50` → **passPlanB 逆序遍历调 `fcn_18005a410`（单步启动）** → passPlanA 遍历调 `fcn_18005a2c0`；轮切换处 EndScene → currentBinding=orderedPlan[k-1] → `fcn_18005c970`（ApplyPassRecord：绑 RT0+深度+viewport+按记录 flags Clear）→ BeginScene；帧末 `fcn_18005e210` → passPlanB 遍历调 `fcn_18005a5c0`（恢复运行）。
3. **ScriptExternal 真身**（核心发现）：它不是回调，是**单步挂起点**。技术级解释器 `fcn_18001bbc0` 的 case 12：单步模式（a4=1）保存下一命令索引到运行上下文并返回；全速模式为空操作。即：轮首跑到 ScriptExternal 为止（此时 G-buffer 已绑定并清空）→ 本轮场景画进这些 RT → 帧末从保存位置续跑（光照/合成 Pass=…）。移植版的 `SasHostScriptExternalColor` 桩因此整个作废。
4. **运行期循环**：LoopByCount/LoopGetIndex/LoopEnd（id 13/14/15）在运行期执行，带循环栈，读实时参数值（原版 `fcn_18001bbc0` case 0xD/0xE/0xF）。移植版的编译期展开是错误简化（ray_controller 靠运行时参数控制）。
5. **`Pass=` 是原版正式命令**（编译器 `fcn_180018200` 引用 "pass" 与 "Error: unknown pass name: "）：编译为 id 0 条目（param=pass 句柄），经 `fcn_18001bf80` 执行（SetTechnique + pass 级脚本或默认宿主绘制槽）。PHASE3 笔记"MME 0.37 无 Pass="是误判；工作区 WIP 的 id 16 扩展应改为原生机制。
6. **命令全集**：id 0=Pass=、1-4=RenderColorTarget0..3、5=Depth、6/7=ClearSetColor/Depth、8=Clear(→宿主 OnClear 0x180058440)、9=（移植版缺失，undocumented，保持接受即忽略）、10/11=Draw=Geometry/Buffer（SetTechnique+宿主槽 0/1）、12=ScriptExternal、13-15=循环。`ClearSetStencil` 为 ray.fx 实际使用（WIP 已接受）✓；值大小写不敏感（WIP 已修）✓；R32F/R16F（WIP 已加）✓。
7. ray.fx 实际脚本已核对：前半 `RenderColorTarget=ScnMap; …Clear…; ScriptExternal=Color;` 恰好一次，后半几十个 `RenderColorTarget=…; Pass=…`，最后合成回后台缓冲。机制完全覆盖（含 MRT：`RenderColorTarget0/1=` 同时设置）。

## 实施步骤（P0 = 机制层，P1 = 材质侧，使 Ray-MMD 完整工作）

**P0-1 运行期脚本解释器重写**（`third_party/mmeffect/src/mmeffect/sas_exec.{h,cpp}`）
- 命令表改为扁平条目（id+param），不再编译期展开循环；删除 id 16 扩展，`Pass=` 编译为原生 id 0。
- 新增运行上下文持久化结构（对齐 0x88 原版布局：命令索引 + 4 个保存的 RT + 深度 + viewport + 暂存清屏色(宿主背景色)/z=1.0 + 循环栈）：现有 SasRunContext 扩展 `commandIndex`、`loopStack`。
- 新 API：`SasExecuteTechniqueStep()`（跑到 ScriptExternal 挂起，返回是否挂起）与 `SasResumeTechnique()`（全速续跑到底，结束销毁上下文）。循环命令运行期求值（effect->GetInt/GetFloat 实时值 + SetInt 写 LoopGetIndex）。
- 保留 WIP 的：大小写归一、ClearSetStencil 接受、R32F/R16F、格式表。

**P0-2 ModelData SAS 绑定接线**（`model_data.h`、`material_bind.cpp`、`emm_manager.cpp`）
- 赋值/自动挂载成功后把 SasParse 的 scriptClass/scriptOrder/hasPostEffect 写入 ModelData（对应 `fcn_18002ca80` L292-320/L451-457）；记录卸载时清零并销毁 +0x358 上下文。
- 绘制抑制：renderClass 1/2 的载体对象（ray.x）不参与正常绘制（对齐 `fcn_18005d340` L107-118 的条件，callbacks.cpp 已有 renderClass 读取，核实接通）。

**P0-3 pass 记录机制落地**（`pass_planner.cpp`、`mme_context.h`、`callbacks.cpp`）
- `MmeApplyPassRecord` 从空桩改为真实现（SetRenderTarget(0)+SetDepthStencilSurface+SetViewport(记录宽高)+按记录 flags/Clear 颜色清屏，对齐 `fcn_18005c970`）；记录的表面/宽高/flags 暂存点对照 `fcn_18005c510`（MmeUpdatePassBookkeeping）实现时核实。
- `MmeReportDrawError` 的 passPlanB 逆序遍历改调 P0-1 的 Step（替代现在"遍历所有 SAS 效果全速跑"的 SasPostEffectVisitor 顶替物）；`MmeRunPostEffect` 的 passPlanB 遍历改调 Resume+销毁（对齐 `fcn_18005a5c0`）。passPlanA 遍历接 `fcn_18005a2c0` 对应逻辑。
- 规划器重复次数对齐原版 `|orderedPlan|+1`（去掉 porter 猜测的额外 +postEffectCount，实现时对照 `fcn_18005b9e0` 尾部与 `fcn_18002baa0`/`fcn_18005fd30` 确认 orderedPlan 组成）。
- `SasHostScriptExternalColor` 桩删除；`SasIsPostTechnique` 回归原版判定（技术脚本含 draw=buffer 即可，Pass= 天然覆盖 ray 模式由 id 0 机制处理）。

**P1-4 对象侧正确性**（`material_bind.cpp`、`sas_interpreter.cpp`）
- 技术选择按 `MmdPass` 注解分发（object/object_ss/shadow/zplot/edge 对应 drawType 1/2/3/5/4；SasGetTechniqueInfo 基础设施已在，SasExecuteTechnique 接上调用点）；MainTec0 名字查找仅作回退。
- CONTROLOBJECT 完整实现：按名字解析骨骼/表情/附件变换（ModelData::findNameIndex 已在；对齐原版解析器 `sub_180057BC0`："(self)/(AttachedModel)/(AttachedBone)/(OffscreenOwner)" 特名 + ExpGetPmdBoneWorldMat + 附件 Si/Tr），替换现有 bone0/morph0 占位。ray.fx 有 ~50 个 CONTROLOBJECT 参数，缺此则控制器全哑。
- `ResourceName` 纹理加载（D3DXCreateTextureFromFileExW，经 d3dx_dyn）——ray 的 light/IBL 纹理需要。
- 核对 17 参数名表与 ray main.fxsub 实际参数名（matWorldViewProject 拼写等），不一致处以原版 kNameTable（0x1800B36A0 字节转储）为准修正。

**P1-5 健壮性**
- 设备 Reset 后 SAS 资源纹理重建钩子（SasEnsureResourceTexture 重跑；PHASE3 建议 #7）。
- 保留 WIP 的 MmeHostLogLine/一次性 Info 诊断；`(default)` 行赋值静默 no-op 与拖拽丢 .fx 扩展名两个已知坑一并修复（mme_dlg.cpp:262-295、:1404-1411）。

## 验证

1. 双架构构建（沿用仓库现有 x64+x86 构建脚本）零警告通过。
2. 对照测试：加载 ray.x（自动挂 ray.fx）+ 模型 + 分配 Main/main.fx + ray_controller.pmx；预期 MMEffect.txt 出现 "running post-effect technique" 且无 unsupported script command 警告；画面出现延迟光照合成（无模型材质时也应有效果变化）。
3. 回归：无效果加载时与 MME 关闭时逐像素一致（直通路径不动）。

## 风险与对策

- 轮次角色细节（turn 0/1 各画什么、ApplyPassRecord 暂存来源）：实现时逐条对照 `fcn_18005c510`/`fcn_18005b9e0`/`fcn_18005da50` 反编译原文（本地已备），不确定处加一次性诊断日志。
- ray.fx 依赖 SM3 + 30+ include：编译路径已验证无恙（ScopedChdir），失败会进 MMEffect.txt。
- 改动集中在 third_party/mmeffect 引擎内部 + 少量宿主接线，宿主渲染管线（frame_scene.cpp 重复循环）不动。
